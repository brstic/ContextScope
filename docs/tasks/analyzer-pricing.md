## Analyzer (packages/analyzer/src)
`createAnalyzer(limits?: Partial<AnalyzerLimits>, pricing?: Pricing): Analyzer` + exported pure helpers.
- comparePrefix(a,b): shared exact prefix via prefixFingerprint chain; first changed index/kind/label in b; sharedEstimatedTokens = sum of estimatedTokens of shared segments (null if any null); note explaining this is structural / cache-eligibility evidence, not proof of a provider cache miss.
- alignSegments: Myers/LCS by exactFingerprint; if a.length×b.length > 4e6 fall back to linear greedy; removed+added at same position with same kind+label → 'changed'.
- Findings (Finding in shared/domain.ts): deterministic id = sha256(type+scope) short hex (stable dedup); evidence with real numbers; recommendation; tradeoff (functional risk); affects; docsUrl to official provider caching docs; estimatedTokenReduction only when defensible (e.g. duplicated segment est. tokens × (copies−1)), else null. Never fabricate savings. Thresholds as exported constants.
  - analyzeRequest: duplicate_segment (same normalizedFingerprint ≥2× in one request, est ≥200 tokens); duplicate_system_instructions (two system/developer segments, same normalized fp); oversized_tool_schemas (tool_definition est sum ≥4000 or ≥40% of request est); large_tool_output (tool_result ≥8000 est); slow_request (duration ≥30 s or ttft ≥10 s); unexpected_cache_writes (reported cacheWrite ≥50% of totalInput and ≥10000); repeated_structured_schema (schema ≥1500 est); history_duplication (same user/assistant exact fp at two different messageIndex in one request).
  - analyzeHistory (chronological, bounded by maxHistory, grouped by sessionId else provider+model): repeated tool schemas (same tool_definition exact fp in ≥5 requests and ≥1000 est: evidence 'The same normalized tool schema appears in N captured requests', type oversized_tool_schemas); unstable_prefix (consecutive requests where first changed segment is tool_definition/system/developer/schema: 'Tool definition changes may reduce reusable prompt-prefix length'); low_cache_reuse (≥5 requests reporting usage, ≥50% of est prefix identical to previous request, but reported cacheRead/totalInput < 10%; phrase as 'reported cache reuse is low although X% of the prefix was identical'; for anthropic mention missing cache_control when cacheControlBlocks==0 and no automatic option); excessive_context_growth (>3× growth over ≥6 turns or a turn adding >20k); repeated_retrieval_payload (document exact fp in ≥3 requests); repeated_large_input (non-tool segment ≥2000 est in ≥5 requests); expensive_model_usage (output price ≥$10/MTok via pricing, input <500 and output <200, ≥5 occurrences, low confidence); token_spike (input >3× group median and >5000).
